    Sổ Tay Hướng Dẫn Quy Trình Solo Builder

    Thiết lập kỷ cương, chia phase phát triển và điều khiển AI Agent chất lượng cao

    PRO WORKFLOW

    1. Giới thiệu triết lý Solo Builder

    Solo Builder là một quy trình làm việc phát triển phần mềm cực kỳ có kỷ luật, được tối ưu hóa đặc biệt cho mối quan hệ cộng tác giữa Nhà phát triển (Con người) & AI Coding Agent (Máy).

    Khi làm việc với các AI Agent tự trị trong các dự án thực tế, các nhà phát triển thường gặp các vấn đề lớn: AI tự ý viết lại code lung tung phá vỡ tính năng cũ (Code Drift), AI bị loãng thông tin khi dự án quá to (Context Bloat), hay việc code chạy tốt nhưng hoàn toàn không có tài liệu và commit rối rắm.

    Quy trình này giải quyết triệt để các vấn đề trên bằng cách định hình AI hoạt động trong một khuôn khổ tuần tự, chia nhỏ các phase độc lập, bắt buộc lên plan chi tiết trước khi code, thiết lập cơ chế nghiệm thu rõ ràng và liên tục đồng bộ trạng thái vào Changelog và Git.

    LỢI ÍCH CỐT LÕI
    Quy trình giữ cho context window của AI luôn tập trung vào đúng Phase hiện tại, giúp tiết kiệm số lượng Token tiêu thụ và hạn chế tối đa các bug phát sinh chéo do sửa đổi file ngoài phạm vi cho phép.

    2. Cấu trúc thư mục tài liệu

    Mọi dự án áp dụng quy trình Solo Builder sẽ lưu trữ thông tin trạng thái đồng bộ tại thư mục gốc của dự án theo cấu trúc như sau: 

    ├── AGENTS.md                  # "Hiến pháp" định hình luật chơi và Tech Stack cho AI Agent
├── CHANGELOG.md               # Lịch sử ghi nhận tính năng theo tiêu chuẩn Keep a Changelog
└── docs/                      # Thư mục chứa tài liệu đặc tả
    ├── brief.md               # Ý tưởng tổng quát và phạm vi dự án (In-Scope/Out-of-Scope)
    ├── BRD.md                 # Tài liệu Yêu cầu Nghiệp vụ (Business Requirements Document)
    └── plans/                 # Thư mục chứa kế hoạch phát triển
        ├── master-plan.md     # Bản đồ lộ trình dài hạn chia theo từng Phase
        ├── phase-1.md         # Kế hoạch chi tiết của Phase 1 (Checklist, Expected Output, Test Guide)
        └── phase-2.md         # Kế hoạch chi tiết của Phase 2...
    VAI TRÒ CỦA AGENTS.MD
    File AGENTS.md là điểm neo tư duy của AI. Agent khi bắt đầu phiên làm việc sẽ tự động đọc file này để hiểu nhiệm vụ, cách chia phase, và tuân thủ tuyệt đối các ràng buộc công nghệ (Tech Stack) do bạn đặt ra.

    3. Hướng dẫn cài đặt Solo Builder Kit

    Để chuyển giao và kích hoạt quy trình Solo Builder cho bất kỳ dự án mới nào, bạn chỉ cần thực hiện các bước sau:

    01

    Sao chép Kit

    Sao chép thư mục solo-builder-kit/ hoặc giải nén file solo-builder-kit.zip vào thư mục gốc của dự án mới của bạn.

    02

    Chạy Setup

    Mở terminal tại thư mục gốc của dự án mới và chạy lệnh setup tự động:

    node solo-builder-kit/setup.cjs
    03

    Nhập Thông Tin

    Nhập tên dự án và danh sách Tech Stack của bạn tại cửa sổ CLI tương tác. Bộ kit sẽ tự tạo các cấu trúc thư mục và cấu hình file rules tự động.

    4. Vòng đời phát triển một Phase (Quy trình PDCA)

    Solo Builder chia quá trình phát triển thành các vòng lặp Phase nghiêm ngặt. Mỗi Phase bắt buộc phải tuân theo chu trình khép kín sau:

    Giai đoạn Hành động cụ thể Sản phẩm đầu ra (Artifacts)
    1. Lập Kế Hoạch Phân tích Master Plan và viết checklist chi tiết các công việc cần làm, xác định chính xác các file sẽ bị tác động. Tạo file docs/plans/phase-n.md
    2. Phê Duyệt Trình bày tóm tắt kế hoạch cho người dùng duyệt trước khi tiến hành viết code. Xác nhận phê duyệt trong khung chat chat
    3. Thực Thi Viết code tuần tự theo từng đầu mục checklist, áp dụng đúng cấu trúc thiết kế. Các file mã nguồn dự án
    4. Nghiệm Thu Cung cấp báo cáo thực thi (Walkthrough) kèm theo tài liệu hướng dẫn manual test từng bước. Tính năng chạy được không lỗi build
    5. Đóng Gói Đưa các cập nhật mới vào Changelog, đánh dấu hoàn thành phase trong Master Plan và commit code sạch. Cập nhật CHANGELOG.md và tạo Git Commit

    5. Kỷ luật quản lý trạng thái dự án

    Để duy trì sự thống nhất và tránh tình trạng AI Agent bị "mất phương hướng" khi dự án phình to, toàn bộ thành viên dự án và AI Agent bắt buộc phải tuân theo 3 kỷ luật thép:

    1. NGUYÊN TẮC SINGLE SOURCE OF TRUTH (NGUỒN SỰ THẬT DUY NHẤT)
    Mọi tính năng, luồng nghiệp vụ và logic tính toán phải được đặc tả trong file BRD.md. Tuyệt đối không bàn luận nghiệp vụ rải rác bên ngoài rồi code chắp vá. Nếu nghiệp vụ thay đổi, hãy sửa đổi tài liệu BRD.md trước, sau đó mới tiến hành code.
    2. TUYỆT ĐỐI KHÔNG NHẢY PHASE (PHASE ISOLATION)
    Chỉ tập trung giải quyết và code các task của Phase hiện tại. Không bao giờ được phép code lấn sang các tính năng của phase sau khi phase hiện tại chưa được nghiệm thu và đánh dấu hoàn thành [x]. Quy tắc này giữ cho mã nguồn luôn ổn định và phạm vi kiểm soát tốt.
    3. KỶ LUẬT STATE SYNC (ĐỒNG BỘ TRẠNG THÁI)
    Mỗi khi kết thúc một nhiệm vụ lớn hoặc sửa một bug quan trọng, bắt buộc phải cập nhật file CHANGELOG.md ngay lập tức. Sau đó tiến hành git add, git commit rõ ràng và git push lên repository để đảm bảo an toàn mã nguồn.

    6. Mẫu câu lệnh tương tác dành cho AI Agent

    Khi giao tiếp với các AI Agent tích hợp trong môi trường Solo Builder, bạn có thể sử dụng các mẫu prompt sau để kích hoạt nhanh các hành vi kỷ luật:

    KHỞI TẠO DỰ ÁN MỚI
    "Hãy đọc hiến pháp AGENTS.md và tài liệu brief.md, sau đó thiết lập kế hoạch Master Plan tổng thể cho dự án mới này."
    BẮT ĐẦU MỘT PHASE MỚI
    "Chúng ta chuẩn bị bước sang Phase 2. Hãy tự khởi tạo file kế hoạch docs/plans/phase-2.md chi tiết theo chuẩn Solo Builder và trình bày plan rút gọn để tôi duyệt."
    ĐÓNG GÓI NGHIỆM THU PHASE
    "Tôi đã chạy các bước nghiệm thu thử nghiệm và mọi thứ hoạt động chính xác. Hãy tiến hành đóng gói Phase, cập nhật CHANGELOG.md, cập nhật master-plan.md thành [x] và đề xuất lệnh commit Git giúp tôi."
